## Reusable gotchas discovered by prior layers (read before you start — avoids repeating known failures)
1. **Solution attachment**: the Python Dataverse SDK's `client.tables.create(..., solution=...)` does not reliably auto-attach the new table to the `poutineleaguecore` solution's component list — it can silently land only in the org Default Solution instead. After creating the table, EXPLICITLY verify it's a member of `poutineleaguecore` and if missing, run `pac solution add-solution-component --component <table-logical-name> --componentType 1` (componentType 1 = Entity) to attach it, then re-verify.
2. **DateTime columns**: not expected to apply to Category, but if you add any date/time field, creating it via the SDK's generic `add_columns()`/`create()` with a plain `"datetime"` type string leaves `DateTimeBehavior` unset, breaking later metadata operations. Workaround: create via raw Web API call with explicit `Format` + `DateTimeBehavior` set from the start.
3. **Choice columns**: if Category has a "computation type" field represented as a choice, use the standard dv-metadata choice-column creation flow (global or local choice set as appropriate).
