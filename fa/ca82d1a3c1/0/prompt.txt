## Scope for this layer: Try table ONLY
Per `ARCHITECTURE.md` §1, Try is "An employee self-declaring they tried a poutine" with: lookup to Poutine Submission, lookup to employee (systemuser), timestamp. The Poutine Submission table (`rpo_poutinesubmission`, layer 3) already exists in Dev with 18 sample submissions — use real records for lookups.

Author as a custom table under the `rpo` publisher prefix:
- Lookup to `rpo_poutinesubmission` (required) — e.g. `rpo_poutinesubmissionid`
- Lookup to `systemuser` for the employee who tried it (required) — e.g. `rpo_employeeid`
- `rpo_triedon` (DateTime) — timestamp of the try

## IMPORTANT: known gotcha from layer 3 (systemuser lookup)
The Python Dataverse SDK's `create_lookup_field()` convenience wrapper auto-generates an invalid relationship schema name when the lookup target is a built-in/OOB table with no customization prefix (e.g. `systemuser`) — Dataverse rejects it since custom `EntityRelationship` schema names must start with a valid publisher prefix. **Workaround**: call `create_one_to_many_relationship()` directly with an explicit `rpo_`-prefixed relationship name (e.g. `rpo_Try_Employee`) instead of the convenience wrapper for this lookup. The lookup to `rpo_poutinesubmission` (a custom table) does not have this problem and can use the normal convenience path.
