## IMPORTANT: known gotchas from earlier layers (avoid repeating them)
1. **systemuser lookup**: the SDK's `create_lookup_field()` convenience wrapper auto-generates an invalid relationship schema name when the lookup target is a built-in table with no customization prefix (e.g. `systemuser`). Workaround: call `create_one_to_many_relationship()` directly with an explicit `rpo_`-prefixed relationship name (e.g. `rpo_Review_Reviewer`) for the reviewer lookup. The lookup to `rpo_try` (a custom table) does not have this problem.
2. **Solution attachment**: verify the new table (and any new relationships) actually land in the `poutineleaguecore` solution's `solutioncomponent` list, not just the org Default Solution — use `pac solution add-solution-component` if the SDK's `solution=` parameter doesn't auto-attach.
3. This layer has no DateTime column, but if you add any timestamp column for any reason, create it via raw Web API with an explicit `Format` + `DateTimeBehavior` (a generic `"datetime"` type string via `add_columns()`/`create()` leaves `DateTimeBehavior` unset and breaks later metadata operations).
