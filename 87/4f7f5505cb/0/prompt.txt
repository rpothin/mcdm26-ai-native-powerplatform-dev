## Scope for this layer: Poutine Submission table ONLY (most complex layer — has real dependencies)
Per `ARCHITECTURE.md` §1 and the ER diagram, Poutine Submission is "A submitted poutine, owned by the submitting employee" with: name/description, price, photo (Dataverse file/image column), status (choice: Draft, Submitted, In Review, Approved, Rejected), lookup to Restaurant, lookup to submitter (systemuser). It also has an N:N relationship to Tag. Both Restaurant (`rpo_restaurant`, layer 1) and Tag (`rpo_tag`, layer 2) already exist in Dev with real sample data — use them for real lookups, do not create placeholders.

Author as a custom table under the `rpo` publisher prefix:
- `rpo_name` (String) — poutine name
- `rpo_description` (String, multiline) — description
- `rpo_price` (Currency or Decimal — your judgment, note the choice in the PR)
- `rpo_photo` (Image column type)
- `rpo_status` (Choice/OptionSet: Draft, Submitted, In Review, Approved, Rejected — default Draft)
- Lookup to `rpo_restaurant` (required)
- Lookup to `systemuser` for the submitter (this is Dataverse's built-in system user table — NOT a custom table; use a standard lookup, e.g. `rpo_submitterid` or the SDK's native customer/owner-style lookup pattern to systemuser)
- N:N relationship between `rpo_poutinesubmission` and `rpo_tag`
